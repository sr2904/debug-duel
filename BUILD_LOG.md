## Phase 0: Setup and hello-world deploy (2026-10-04)

### What was built
- Scaffolded the DeepSpace starter in place with `npm create deepspace@latest .`. This gives a Vite + React frontend and a Hono worker with Durable Objects already wired up.
- Registered the app with `npx deepspace app init`, which minted the app id and made the initial commit.
- Replaced the starter landing page (`src/pages/index.tsx`), the `<title>` in `index.html`, and the SEO title and description in `src/seo.ts` with "Debug Duel — coming soon" copy. Kept the scaffold's sign-in flow and `/home` route so auth can be tested on the live site.
- Ran the app locally with `npx deepspace dev start` (http://localhost:5173).
- Pushed to GitHub and deployed. The release is `rel_01M44S6EXV0WQ12K747H0G83ZG`, with `serving: confirmed` and `dataPlane: confirmed`.

### Key decisions and why
- **Node 24 (v24.21.0), installed locally in `~/.local/node24`.** DeepSpace supports `>=22.15 <23 || >=24 <25 || >=26 <27`; the machine had Node 25, which is excluded. Homebrew's `node@24` tried to build Node and LLVM from source because the Command Line Tools are outdated, so I stopped it and used the official prebuilt tarball from nodejs.org instead, after checking its SHA-256 checksum. To run project commands: `export PATH=~/.local/node24/bin:$PATH`.
- **GitHub as the source of truth.** Reviewers can browse the repo. Deploys ship the local working tree. Because this is permanent, I checked `deepspace status --json` (`sourceInference: "github"`) before the first deploy. Never run `deepspace push`.
- **Branch renamed from `master` to `main`** before the first push.
- **Secrets:** none yet. The scaffold's `.gitignore` already covers `.dev.vars*`, `.deepspace`, `.wrangler`, and `.claude/launch.json`. `.dev.vars` is generated by the CLI from the secrets store and is never edited by hand.

### Early finding for Phase 1 (sandbox)
DeepSpace's sandbox is **Anthropic's hosted code-execution tool, which Claude drives** (`codeExecutionTool()` + `streamText`). It is not a direct "run this JS" API. Cloudflare Workers also block `eval` and `new Function`, so player code can't run in the worker itself. The Phase 1 spike will measure latency, cost, and reliability, plus the risk that player code contains prompt injection aimed at Claude.

### What went wrong and how it was fixed
- **The first `brew install node@24` broke Shashwat's Homebrew Node 25.** While installing dependencies, Homebrew upgraded `simdjson`, and the installed `node` (25) links against the old `libsimdjson.31.dylib`, so it now fails to start. I had wrongly said Node 25 was "untouched". **Fix (Shashwat will run it): `brew reinstall node`.** Lesson: a dependency upgrade in a brew install can break other brew formulae, so prefer an isolated prebuilt runtime.
- **I cut off the brew error.** I piped the first install through `tail -5`, which lost the actual error. On the retry I logged the full output, which showed the build from source.
- **`npm create deepspace .` refused because of `skills-lock.json`.** I moved that file to a scratch folder, scaffolded, and confirmed the scaffold wrote an identical file.
- **`deepspace auth login` from Claude Code's `!` prompt** failed with `interactive_required`, because it isn't a TTY. Shashwat logged in from a normal Terminal instead.
- **Live logs showed 18 × `GET /ws/app:… → 404`.** I checked them: a plain GET gets 404, but a real WebSocket upgrade gets `101`. All 18 came within about 9 seconds of the deploy, during its "data plane confirmed" check, so they were the deploy's own probes, not broken sync.
- **The dev server was killed** by Claude Code's 30-minute limit on background commands. I restarted it with a 2-hour limit. For long sessions, run `dev start` in your own Terminal.
